# moneyCalculating

회식 1/n 계산기. 안주는 다 같이, 술은 마신 사람끼리 나눠 냅니다.

## 실행

```bash
npm install
npm run dev     # http://localhost:5173 (같은 와이파이의 휴대폰에서도 접속 가능)
npm run build   # dist/ 에 정적 파일 생성
npm run preview
```

## 사용 흐름

1. **참가자** — 오늘 자리에 있는 사람을 모두 넣습니다.
2. **메뉴** — 메뉴 이름과 **단가**, **수량**을 넣습니다. 줄 합계는 `단가 × 수량` 입니다.
   맨 위 **빠른 추가** 칸에 `삼겹살 15000 x2` 처럼 한 줄로 치고 Enter 를 누르면 바로 들어갑니다
   (아래 [빠른 추가](#빠른-추가) 참고). 지난 회식에서 쓴 메뉴는 **자주 쓰는 메뉴** 칩으로 떠서
   눌러 넣기만 하면 됩니다. 아래 상세 폼도 그대로 있어서 편한 쪽으로 쓰면 됩니다.
   목록의 `−` `+` 로 메뉴를 열지 않고 수량만 바로 올리고 내릴 수 있습니다(한 병 더 시켰을 때).
   나누는 방식은 **공통 메뉴**(참가자 전원)와 **개별 메뉴**(다음 단계에서 고른 사람만) 둘 중 하나입니다.
3. **배정** — 공통이 아닌 메뉴는 아무도 없는 상태로 시작합니다. 칩을 누르면 개수가 하나씩 올라가고,
   주문 수량까지 채우면 0으로 돌아갑니다(수량 1짜리는 그냥 켜고 끄기). 참가자별 보기에는 `비우기`도 있습니다.
   **메뉴별**(메뉴 하나에 먹은 사람들을 넣기)과 **참가자별**(사람 하나에 먹은 메뉴들을 넣기) 중
   편한 쪽으로 전환할 수 있습니다. 둘은 같은 데이터를 다르게 보여줄 뿐이라 어느 쪽으로 눌러도 결과가 같습니다.
   고른 보기는 저장돼서 새로고침해도 유지됩니다.
   아무도 없는 메뉴가 남아 있으면 다음으로 넘어가지 않습니다.
4. **정산** — 1인당 금액이 나옵니다. 이름을 누르면 어떤 메뉴에서 얼마가 나왔는지 펼쳐집니다.

## 빠른 추가

메뉴 하나를 넣는 데 칸을 오가지 않게, 맨 위에 한 줄짜리 입력을 따로 뒀습니다.
`이름 · 금액 · 수량` 순서로 쓰고 Enter 를 누르면 목록에 붙고 커서는 그 자리에 남습니다.

| 친 것 | 읽히는 것 |
| --- | --- |
| `삼겹살 15000` | 삼겹살 · 15,000원 · 1개 |
| `삼겹살 15,000 x2` | 삼겹살 · 15,000원 · 2개 |
| `소주 5000 3개` | 소주 · 5,000원 · 3개 |
| `삼겹살 15000 2` | 숫자가 둘 연달아 끝나면 뒤엣것이 수량입니다 |
| `삼겹살 2인분 30000` | `2인분` 은 가운데라 이름에 그대로 남습니다 |
| `삼겹살15000` | 붙여 써도 됩니다 |
| `삼겹살` | 금액 없이 이름만. 아래 상세 폼으로 넘겨 금액 칸에 커서를 둡니다 |

- 수량 표시는 `x2` `*2` `×2` `2개` `2병` `2잔` `2인분` `2ea` `2pcs` 를 알아봅니다. 띄어 써도 됩니다.
- **수량 표시가 없으면 마지막 숫자는 언제나 금액입니다.** 그래서 `콜라500ml 2000` 같은 것도 안 깨집니다.
- 친 대로 어떻게 읽혔는지 입력칸 바로 아래에 그 자리에서 보여 줍니다. 틀리면 Enter 전에 고치면 됩니다.
- 옆의 **공통 / 개별** 은 한 번 고르면 다음 줄에도 그대로 갑니다. 술을 연달아 넣을 때 매번 누르지 않게요.
- 파싱은 `src/stores/settlement.js` 의 `parseQuickAdd()` 하나에 모여 있습니다.

상세 폼에서는 **이름 칸에서 Enter 를 누르면 금액 칸으로**, 금액 칸에서 Enter 를 누르면 저장하고
다시 이름 칸으로 돌아옵니다. 손을 키보드에서 떼지 않고 계속 넣을 수 있습니다.

## 자주 쓰는 메뉴

메뉴를 넣을 때마다 이름과 금액을 따로 모아 둡니다. 가는 집이 반복되니 다음 회식에서 그대로 꺼내 씁니다.

- 칩을 누르면 바로 들어갑니다. **같은 걸 또 누르면 줄이 하나 더 생기지 않고 수량이 올라갑니다.**
- 같은 이름은 한 줄로 합치고 금액은 마지막에 넣은 값으로 갱신합니다. 가격이 오르면 목록도 따라 오릅니다.
- 자주 쓴 순으로, 같으면 최근에 쓴 순으로 8개까지 띄웁니다. 30개까지 들고 있습니다.
- **`편집`** 을 누르면 이름과 금액을 그 자리에서 고치거나 `×` 로 지웁니다. 접혀 있던 것까지 다 나옵니다.
- **통화는 섞지 않습니다.** 원으로 넣은 15,000원짜리가 달러 화면에서 `$15,000.00` 로 보이면 안 되니,
  지금 통화로 넣은 것만 띄웁니다. `목록 비우기` 도 지금 통화 것만 지웁니다.

저장 칸이 계산서(`hoesik.settlement.v1`)와 따로입니다(`hoesik.recent.v1`).
그래서 **`처음부터` 로 계산서를 지워도 이 목록은 남습니다.** 목록을 지우려면 `편집 → 목록 비우기` 입니다.

## 계산 규칙

- 한 줄에 붙는 금액은 `단가 × 수량` 입니다. 나누는 대상은 이 줄 합계입니다.
- 공통 메뉴: 참가자 **전원**이 1/n
- 개별 메뉴: **가져간 개수에 비례**해 나눕니다. 모두 1개씩이면 그냥 1/n 입니다.
  예를 들어 냉면 3개 30,000원에서 가가 2개, 나가 1개면 가 20,000원 · 나 10,000원.
- 개수의 합이 주문 수량과 달라도 됩니다. 줄 합계를 개수 비율로 나누므로 돈이 새거나 넘치지 않습니다.
- 1원 단위까지 정수로 쪼개고, 나누어떨어지지 않는 나머지 1원은 명단 앞사람부터 한 번씩 붙습니다.
  그래서 걷는 단위가 1원이면 각자 낼 금액의 합이 결제 총액과 정확히 맞습니다.
- 걷는 단위는 **내림**입니다. 걷는 총액이 결제 총액을 절대 넘지 않습니다.
  예를 들어 16,000원을 3명이 나누면 1인당 5,333원이고, 1,000원 단위에서는 5,000원씩 걷습니다.
- 내림하고 덜 걷힌 금액은 정산 화면에 **남은 금액**으로 표시됩니다. 위 예시라면 1,000원입니다.

## 언어

UI·UX는 그대로 두고 문구만 바꾸는 3개 언어를 지원합니다. 주소가 곧 언어입니다.

| 주소 | 언어 | `<html lang>` |
| --- | --- | --- |
| `/` | 한국어 | `ko` |
| `/ja/` | 日本語 | `ja` |
| `/en/` | English | `en` |

GitHub Pages에는 서버 rewrite가 없어서, `index.html` · `ja/index.html` · `en/index.html` 을
각각 실제 파일로 빌드합니다(`vite.config.js` 의 `rollupOptions.input`). JS·CSS 번들은 셋이 공유하므로
언어를 바꿔도 다시 받지 않습니다. 화면 코드는 `document.documentElement.lang` 하나만 보고 언어를 정합니다.

문구는 전부 `src/i18n.js` 한 파일에 있습니다. 세 언어의 키 개수가 같아야 하고, 없는 키는 한국어로 떨어집니다.

머리말의 `한국어 / 日本語 / English` 링크로 이동하며, 저장된 계산서는 같은 도메인이라 그대로 남습니다.

## 통화

언어와 별개로 머리말에서 **원 · 엔 · 달러**를 직접 고릅니다. 처음 열 때만 언어로 짐작하고(한국어→원,
일본어→엔, 영어→달러), 그 뒤로는 고른 값을 저장해 따릅니다. 영어 화면에서 원으로 계산해도 됩니다.

| 통화 | 표기 | 소수 | 걷는 단위 |
| --- | --- | --- | --- |
| 원 | `15,000원` | 없음 | 1 / 10 / 100 / 1,000원 |
| 엔 | `15,000円` | 없음 | 1 / 10 / 100 / 1,000円 |
| 달러 | `$150.00` | 센트 2자리 | $0.01 / $0.10 / $1 / $5 |

금액은 내부적으로 **최소 단위 정수**(원·엔은 1, 달러는 1센트)로만 다룹니다. 부동소수점 오차 없이
1/n 이 떨어지고, 나머지 1센트도 명단 앞사람부터 정확히 배분됩니다.

> 통화를 바꿔도 **환율 계산은 하지 않습니다.** 적어 넣은 숫자는 그대로 두고 단위만 갈아 끼웁니다
> (달러로 바꾸면 소수 두 자리가 생기므로 `16000` → `$16,000.00` 처럼 자릿수만 맞춥니다).

> 각 HTML의 `canonical` · `hreflang` 은 `https://pokohen.github.io/moneyCalculating/` 기준 절대 URL입니다.
> 배포 주소를 바꾸면 세 HTML 모두 고쳐야 합니다.

## 저장

계산서는 브라우저 `localStorage`(`hoesik.settlement.v1`)에 저장됩니다. 새로고침해도 그대로 남고,
`처음부터` 또는 정산 화면의 `처음부터 다시하기`로 지웁니다.

[자주 쓰는 메뉴](#자주-쓰는-메뉴)는 `hoesik.recent.v1` 에 따로 저장돼서 계산서를 지워도 남습니다.

서버로 나가는 데이터는 없습니다.
